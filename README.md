# Сайт психолога — версия на Supabase

Переписанная версия сайта: тот же дизайн, цвета и структура, но вместо Python-бэкенда используется **Supabase** (Postgres + Auth). Отдельный сервер больше не нужен — сайт разворачивается как статический фронтенд.

## Что внутри

- **React + Vite + Tailwind** — фронтенд (полностью сохранены цвета, тёмная тема, структура страниц)
- **Supabase** — база данных, авторизация, вся логика теста
- **[supabase/schema.sql](supabase/schema.sql)** — полная схема БД: таблицы, права доступа (RLS), функции и все вопросы теста

## Логика теста (исправлена)

Каждый из 35 вопросов привязан к своему классу-архетипу (`questions.archetype_code`).
Подсчёт выполняется в базе функцией `complete_test`:

1. Каждый ответ «Да» даёт +1 балл архетипу, к которому относится вопрос
2. Максимум 5 баллов на архетип
3. Всегда возвращаются все 7 классов пола (отсутствующие — с нулём)
4. По баллам каждому классу присваивается статус: **A** (4–5) активный, **M** (3) средний, **N** (2) неопределённый, **P** (0–1) пассивный
5. Ведущий архетип — класс с максимальным баллом; результат сохраняется в `test_results`, профилю выдаётся код результата `PSY-...` (по нему открывается страница результатов)

## Настройка (один раз, ~10 минут)

### 1. Создайте проект Supabase

На [supabase.com](https://supabase.com) → **New project** (бесплатного тарифа достаточно).

### 2. Выполните схему

**SQL Editor** → **New query** → вставьте содержимое файла `supabase/schema.sql` целиком → **Run**.
Создадутся все таблицы, политики безопасности, функции и вопросы теста.

### 3. Отключите подтверждение email

**Authentication → Providers → Email** → выключите **Confirm email**.
(Сайт использует вход по логину и паролю; email внутри — технический, письма никуда не отправляются.)

### 4. Настройте ключи

```bash
cp .env.example .env
```

В `.env` впишите значения из **Project Settings → API**:

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

### 5. Запуск

```bash
npm install
npm run dev        # локально: http://127.0.0.1:3000
npm run build      # сборка для продакшена (папка dist)
```

### 6. Назначьте себя админом

Зарегистрируйтесь на сайте, затем в **SQL Editor** выполните:

```sql
update public.profiles set role = 'admin' where login = 'ВАШ_ЛОГИН';
```

После перезахода в аккаунт появится доступ к админ-панели (`/admin`).

## Деплой

Проект — статический сайт, деплоится на Vercel/Netlify без сервера:

- **Vercel**: импортируйте репозиторий, добавьте переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в настройках проекта. `vercel.json` уже настроен для SPA-роутинга.

## Структура проекта

```
supabase/schema.sql        — вся схема БД и логика (выполняется в Supabase)
src/lib/supabase.js        — клиент Supabase
src/api/api.js             — слой данных (тот же интерфейс, что у старого API)
src/context/AuthContext.jsx — авторизация через Supabase Auth
src/hooks/useScrollReveal.js — глобальные scroll-анимации
src/pages/                 — страницы (дизайн без изменений)
public/audio/              — аудио практик
src/assets/                — фотографии
```

## Что нового по сравнению со старой версией

- Убран Python/FastAPI бэкенд и отдельный хостинг для него
- Логика подсчёта теста перенесена в Postgres-функции — считается атомарно и одинаково для всех
- Исправлен подсчёт: каждый вопрос всегда даёт балл строго своему классу-архетипу, все 7 классов присутствуют в результате
- Безопасность: RLS-политики (каждый видит только своё, админ — всё), роли нельзя поднять самому себе
- Анимации: плавные переходы между страницами, scroll-reveal на всех страницах, анимация смены вопросов, каскадное появление и рост полос на странице результатов
